# Security Policy

## Supported Versions

The following versions of XNAT currently receive security updates:

| Version | Supported          |
| ------- | ------------------ |
| Latest  | :white_check_mark: |
| Older   | :x:                |

Please check [xnat.org](https://www.xnat.org/) for the current supported release series.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues.**

If you believe you have found a security vulnerability in XNAT, please report it
by emailing **security@xnat.org**.

Include as much of the following information as possible to help us understand
and reproduce the issue:

- Type of issue (e.g., SQL injection, cross-site scripting, authentication bypass)
- Full paths of source file(s) related to the issue
- Location of the affected source code (tag/branch/commit or direct URL)
- Any special configuration required to reproduce the issue
- Step-by-step instructions to reproduce the issue
- Proof-of-concept or exploit code (if possible)
- Impact of the issue, including how an attacker might exploit it

You should receive a response within **5 business days**. If you have not heard
back, please follow up to ensure the original message was received.

## Disclosure Policy

After a security report is received, we will:

1. Confirm the problem and determine the affected versions.
2. Audit code to find any similar problems.
3. Prepare fixes for all still-supported releases.
4. Release patched versions and publish a security advisory.

We kindly ask that you give us reasonable time to address the vulnerability
before any public disclosure.

## Bug Bounty

There is currently **no bug bounty program** for XNAT. We are grateful for
responsible disclosures and will acknowledge reporters in release notes where
appropriate.
